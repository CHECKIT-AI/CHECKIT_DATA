# 검색 기준선 평가

BM25를 추가하기 전의 BGE-M3 dense 검색 결과를 보존합니다. 기존 검색 코드는 수정하지 않습니다.

## 실행

CheckIt_Data 루트에서:

```bash
source .venv/bin/activate
python -m RAG.pipelines.evaluate --corpus labor_standards_v001 --run-name baseline_bge_m3
```

기본 질의 파일은 data/rag/evaluation/retrieval_dev_v002.jsonl입니다.
15개 주제에 법률 키워드·사용자 질문·계약서 문구를 각각 2개씩 두어 총 90개입니다. 유형별 30개이며 기존 v001의 12개 문장을 포함합니다. 기존 파일과 기존 측정 결과는 보존합니다.
정답은 수집 원문의 제목·내용을 바탕으로 지정한 대표 조문 후보이며 annotation_status=DRAFT입니다.
법률 전문가 검수를 거친 정답 데이터나 위법 판정 정답이 아닙니다.
가능한 모든 관련 조문을 망라하지 않으므로 초기 회귀 점검용으로 사용하세요.

## 결과

outputs/rag/baseline_bge_m3_<UTC실행시각>/ 아래에 다음 파일을 만듭니다.

- results.csv: 질의별 정답 후보 순위·상위 결과·처리 시간
- results.jsonl: 상위 10개 결과의 본문·메타데이터 포함 원본 평가 결과
- summary.json: 전체 및 키워드/사용자질문/계약문구별 Hit@K, Recall@K, MRR@10
- run_metadata.json: 질의셋·청크·인덱스 명세 해시, 모델 커밋·패키지 버전·측정 조건

Hit@5는 대표 정답 중 하나라도 상위 5개에 있는 질의의 비율입니다.
Recall@5는 질의마다 지정한 관련 정답 조문 중 상위 5개에서 찾은 비율을 평균한 값입니다.
현재 질의별 정답이 하나이므로 Hit@K와 Recall@K가 같습니다.
MRR@10은 상위 10개 내 첫 정답 순위의 역수 평균이며, 정답이 10위 밖이면 0입니다.
실행 시간은 검색기를 준비·워밍업한 후 질의 처리와 최종 상위10개 검색을 측정합니다. hybrid는 내부 후보 검색과 RRF 통합을 포함합니다.
아직 실제 서비스 전체 응답 시간이나 반복 실행의 통계적 성능 비교는 아닙니다.

## 이후 비교

질의셋을 검수한 뒤 고정하고, 같은 질의셋 해시·청크 해시·모델 커밋·최종 검색 깊이로 비교하세요.
질의를 수정했다면 새 데이터셋 버전으로 저장하고 baseline도 다시 측정해야 합니다.
현재 90개는 직접 작성한 개발·회귀 점검용 질의이며 실제 수집 계약서 사례 90건을 의미하지 않습니다. 같은 주제의 변형 문장은 서로 독립적인 사례가 아닙니다. 여기에 맞춰 검색을 조정한 뒤 이를 미사용 최종 테스트셋으로 보고하면 안 됩니다.
평가기의 --method dense|bm25|hybrid 옵션으로 방식을 선택하고 별도 run-name으로 결과를 보존합니다. 한 번에 비교하려면 RAG.pipelines.compare_retrieval을 사용하세요. 세부 사용법은 test/rag/HYBRID.md를 참조하세요.

## v002 비교 시 유의점

기존 12개 평가와 새 90개 평가는 질의 분포가 달라 점수만 직접 비교하면 안 됩니다. BM25 통합 전후는 동일한 v002 90개와 동일한 corpus로 비교하세요. 현재 자료는 근로기준법만 대상으로 하며 최저임금법·기간제법 등은 포함하지 않습니다. 향후 여러 조문이 관련된 질의의 정답 범위를 추가 검수해야 합니다.

기존 v001만 재평가하려면 --dataset data/rag/evaluation/retrieval_dev_v001.jsonl 을 명시하세요.
