## 4. BM25와 통합 설정

- BM25Okapi: k1=1.5, b=0.75, epsilon=0.25. 점수가 0보다 큰 문서만 반환.
- Kiwi 0.24.0 CoNg: NFKC·소문자 정규화, 조사·어미·문장부호 제외, 부정 표현·숫자·조문 식별자 보존.
- BGE-M3와 같은 chunks.jsonl의 embedding_text를 BM25 문서로 사용.
- hybrid: dense 상위 20개 + BM25 상위 20개, chunk_id 기준 동일 가중치 RRF, k=60. 통합 후 최종 10개.
- RRF는 원래 검색 점수 대신 순위를 사용합니다. 두 목록에 모두 등장한 문서가 높은 점수를 받을 수 있습니다.
- 쿼리 확장·법률 동의어 사전·reranker·정답 조문 강제 삽입은 적용하지 않았습니다.
- 패키지 버전·코드 해시·BM25 토큰화 설정은 각 run_metadata.json에 기록돼 있습니다.

## 5. 현재 결과에서 관찰된 점

| 질의 유형 | dense Hit@5 | BM25 Hit@5 | hybrid Hit@5 |
|---|---:|---:|---:|
| keyword | 96.7% | 100.0% | 100.0% |
| user_question | 93.3% | 63.3% | 83.3% |
| contract_clause | 83.3% | 80.0% | 80.0% |

- dense 대비 hybrid의 Hit@5는 2개 질의에서 개선되고, 5개에서 악화됐습니다.
- BM25는 법률 키워드에서는 강했지만 사용자 질문에서는 낮았습니다. 이를 dense와 동일 가중치로 결합하면서 일부 기존 정답이 밀렸습니다.
- 예: “해고 이유와 날짜를 종이에 적어 주지 않고 말로만 통보해도 되나요?”의 제27조는 dense 1위에서 hybrid 6위로 내려갔습니다.
- 예: “퇴사한 뒤 남은 월급은 언제까지 받아야 하나요?”의 제36조는 dense 1위에서 hybrid 6위로 내려갔습니다.
- “중도 퇴사하면 위약금 50만 원을 지급한다.”의 제20조는 dense 상위10개 밖, BM25 2위, hybrid 9위였습니다.
- 사용자 질문 Hit@10은 dense 93.3%, hybrid 96.7%지만 Hit@5는 dense 93.3%, hybrid 83.3%였습니다. 일부 후보를 더 찾으면서도 상위 순위 배치가 나빠진 사례가 있다는 뜻입니다.
- 토큰별 점수를 확인한 사례: “퇴사한 뒤 남은 월급은 언제까지 받아야 하나요?”에서 제36조와 겹친 유효 토큰은 하뿐이었습니다. 퇴사/월급과 법령의 퇴직/임금 사이 표현 차이가 있었습니다.
- “종이에 적어 통보” 질문에서는 제27조의 서면/통지 표현과 충분히 겹치지 않고, 제24조의 해고/이유/말/통보 등이 더 높은 BM25 점수를 받았습니다. 이것은 해당 두 질의에서 확인한 어휘 불일치 사례이며 전체 실패 원인을 단정하는 것은 아닙니다.
- 현재 기본 검색은 dense로 유지합니다.

## 6. 당시 제안한 다음 개선 실험: 가중치·재정렬 실행 결과는 8절 참조

1. **weighted_rrf**: 동일 가중치 대신 BGE-M3를 더 신뢰하는 소수의 사전 지정 가중치로 개발셋 실험. 기존 결과 보존.
2. **union_candidates_then_rerank**: dense와 BM25 후보 합집합을 RRF 최종 10개로 자르기 전에 reranker로 재정렬. 후보 Recall과 최종 순위를 구분 측정.
3. **bm25_query_and_fields**: 불용어·질문 표현, 법률 제목/본문 가중치, 월급→임금 등 검색 확장을 개별 실험. 원문과 생성 확장을 구분 보존.
4. **independent_evaluation**: 현재 90개는 개발셋으로 유지. 별도로 수집·검수한 미사용 질의에서 최종 효과 확인.

90개 개발셋을 보며 선택한 설정의 최종 성능은 별도 미사용 평가셋으로 확인해야 합니다. 후보 내 정답 포함률과 재정렬 후 Hit@1·Hit@5를 나눠 측정하면 누락 문제와 순위 문제를 구분할 수 있습니다.
