# 라벨 + 조항 원문 검색 연결 검증

2026-10-28. 기본 corpus: employment_basic_v004, dense 검색, 정책 labels_soft_priority_v1.

## 입력과 동작

```json
{"clause_id":"clause_007","labels":["임금"],"text":"월급에서 회사 대여금을 매달 공제한다.","top_k":5}
```

- 원문만 임베딩하며 라벨 문자열을 원문에 섞지 않는다. 금액·시간·날짜·부정 표현을 가명 값으로 바꾸지 않는다.
- 전체 인덱스에서 상위 20개 후보를 조회한 뒤 라벨과 연결된 근거에 제한된 보너스를 적용한다. 라벨로 법령을 제외하지 않는다.
- dense는 `-cosine_distance`에 최대 0.015를 더한다. 실험 재정렬 방식은 raw logit에 최대 0.05를 더한다. 복수 라벨이어도 보너스를 누적하지 않는다. 값은 확률이 아니다.
- `그 외`는 우선순위 보너스가 없으며 검색을 생략하지 않는다. 라벨 매핑은 개발용 연결이고 적용 요건·위법 판단 규칙이 아니다.
- 결과의 `clause_id`, `labels`, `retrieval_policy`로 분류·원문과 연결하고 각 hit의 `base_rank`, `matched_labels`, `label_priority_score`로 순위 변경을 확인한다.
- 기존 query 입력은 유지하되 조항 형식과 섞어 보내면 거부한다. 중복·미지원·빈 라벨과 빈 원문도 거부한다.

## 개발 평가 결과

기존 90개 개발셋에서 계약서 문장 30개만 추출하고 주제별 라벨을 수동 지정했다. 실제 분류 모델을 실행한 것이 아니며 실제 계약서 원본 평가도 아니다.

| 방식 | Hit@1 | Hit@3 | Hit@5 | MRR@10 |
| --- | ---: | ---: | ---: | ---: |
| 원문 단독 | 66.7% | 76.7% | 93.3% | 0.7478 |
| 수동 라벨 + 원문 | 70.0% | 83.3% | 93.3% | 0.7828 |
| 의도적 오라벨 + 원문 | 66.7% | 80.0% | 93.3% | 0.7506 |

세 방식 모두 Hit@5 28/30으로 같았다. 라벨 입력은 첫 정답 순위 일부를 개선했지만, 이 표본에서 새로운 정답 발견 수는 늘지 않았다. 의도적 오라벨 실험도 같은 28/30이었으나, 모든 오분류에 안전하다는 뜻은 아니다. 정답 라벨·오라벨을 수동으로 정한 합성 DRAFT이므로 실제 분류 모델 출력 및 실제 조항으로 별도 평가해야 한다.

## 검증과 재현

- Data 단위 테스트 24개, 백엔드 RAG 테스트 22개 통과.
- 데이터셋: `../../datasets/retrieval_labeled_clauses_v001.jsonl`.
- `summary.json`, `deltas.json`, `results.json`, `run_metadata.json`에 결과와 코드·입력 해시 보존.
- `api_smoke.json`: 실제 인증·CSRF를 포함한 조항 4건, 기존 query 1건, 중복 라벨 거부 확인.

```bash
python3 -m RAG.pipelines.evaluate_clauses
```

결과 폴더가 이미 있으면 덮어쓰지 않는다. 현재 PC는 평가를 완료했으므로 재실행하려면 출력 버전을 변경해야 한다. 현재 분류 모델 자체·OCR·위법 판정·설명 생성은 연결하지 않았다.
