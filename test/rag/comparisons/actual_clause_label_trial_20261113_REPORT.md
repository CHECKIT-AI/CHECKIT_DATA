# 실제 조항 문구와 분류 모델 라벨 검색 시험 (2026-11-13)

합성 계약서 벤치마크에서 **원문이 있는 문제 조항** 중 지정 정답 조문이 있는 63건(서로 다른 문구 19개)을 사용했다. 원문이 없는 누락 29건은 이 조항 단위 시험에 포함하지 않았다. 정답 조문이 없는 UT06 4건도 제외했다. PDF OCR과 실제 조항 분리는 실행하지 않았고, 벤치마크의 `clause_text`를 그대로 입력했다. 계약일·인덱스·운영 코드는 변경하지 않았다.

백엔드의 실제 `hur03/checkit-contract-classifier-core-synthetic-3epoch-v2` revision `1accf527c060396c5801b044e2cebf8bedb5ac12`로 각 문구를 분류했다. 63건 중 60건에서 예측 라벨과 벤치마크 라벨이 하나 이상 겹쳤고 46건은 집합이 같았다. 이는 **검색 성능이 아니라 라벨 일치**다.

| 입력 및 방식 | Hit@1 | Hit@5 | 설명 |
| --- | ---: | ---: | --- |
| 원문만, 현재 기본 `dense_bm25_top5` | 26/63 (41.3%) | 35/63 (55.6%) | 현재 기준 |
| 원문 + 실제 예측 라벨, 현재 기본 방식 | **26/63 (41.3%)** | **35/63 (55.6%)** | `search_clause`가 라벨을 받지만 이 방식에서는 순위에 사용하지 않음 |
| 원문만, 과거 `dense` 방식 | 19/63 (30.2%) | 35/63 (55.6%) | 방식 비교용 |
| 원문 + 실제 예측 라벨, `dense`의 작은 라벨 보너스 | 20/63 (31.7%) | 35/63 (55.6%) | Hit@1 +1건, Hit@5 변화 없음 |
| 원문만, 후보풀 전체 BGE Reranker 재정렬 | 19/63 (30.2%) | 40/63 (63.5%) | Hit@5 새로 14건·기존 9건 손실; Hit@1 악화 |

현재 BE는 실제 조항을 분류해 `search_clause(text, labels, ...)`에 라벨을 전달한다. 그러나 Data의 기본 `dense_bm25_top5` 분기에서는 `retrieval_policy=None`이고 라벨 우선순위를 적용하지 않는다. 재정렬 시험은 오직 원문으로 dense 후보(최대 21개)와 BM25 상위 10개의 합집합을 만든 뒤 BGE Reranker로 채점했다. 이 시험에는 문제 코드, 쟁점 설명, 정답 조문이 검색 입력으로 들어가지 않았다.

기존 [쟁점 명시 시험](query_rewrite_trial_20261113_REPORT.md)의 Hit@5 78/92는 벤치마크의 `issues.reason`을 미리 입력한 **oracle 쟁점** 조건이다. 실제 계약서 문구나 분류 라벨만 넣은 성능으로 해석하면 안 된다. 또한 지정 조문 ID 일치율은 법적 관련성 전체를 측정하지 않는다.

누락은 계약서에 해당 조항 원문이 없는 경우다. 실제 BE는 계약서 전체 문장과 분류 결과를 검사해 누락 후보를 만들고, 후보의 설명을 법령 검색 질의로 사용한다. 벤치마크의 `… 누락 누락 여부`는 이 실제 검색 입력과 다르므로, 누락 29건의 이전 검색 점수를 실서비스 성능으로 볼 수 없다. 실제 누락 후보 생성부터의 평가가 별도로 필요하다.

질의별 예측 라벨, 방식별 지표와 상위 조문은 [결과 JSONL](actual_clause_label_trial_20261113_results.jsonl)에 있다.
