# 상위 5개 재정렬과 계약서 근거 선택 평가 (2026-11-13)

`employment_basic_v004`의 기본 `dense_bm25_top5`와, 그 결과 상위 5개를 `BAAI/bge-reranker-v2-m3`로 다시 정렬하는 실험 방식을 비교했다. BM25에서 새로 삽입된 5위 후보도 재정렬 대상이다. 모델은 준비된 revision `953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e`을 사용했다. 기본 검색 방식은 변경하지 않았다.

| 질의 | 수 | 기본 Hit@1 | 재정렬 Hit@1 | 두 방식 Hit@5 |
| --- | ---: | ---: | ---: | ---: |
| 별도 작성한 계약 조항 개발셋 | 50 | 31/50 (62.0%) | 28/50 (56.0%) | 42/50 (84.0%) |
| 40개 합성 계약서 벤치마크의 정답 지정 질의 | 92 | 30/92 (32.6%) | 19/92 (20.7%) | 43/92 (46.7%) |

계약 조항 개발셋의 기존 1위 정답 8개가 재정렬 후 2~5위로 내려갔고, 5개가 1위로 올라왔다. 재정렬은 이 두 자료에서 Hit@1을 낮춰 운영 기본값으로 채택하지 않았다. 평균 질의 시간은 개발셋 약 117→359ms, 계약서 벤치마크 약 24→357ms였으나 반복 실행의 지연시간 통계는 아니다.

계약 조항 개발셋에서 정답이 2~5위였던 11개 중 2개는 5위, 9개는 2~3위였다. 예를 들어 임금 지급일 문구에서 휴가수당 지급일 조문이 1위로 나오는 등 인접한 법률 개념과 조문의 구분이 주요 오류였다. 이 사례들은 잠정 정답이므로 법률 전문가의 관련 조문 검수가 선행되어야 한다.

## 40개 계약서의 후보 중 인용 선택

`CheckIt_Eval_Benchmark/ground_truth/retrieval_queries.jsonl`의 96개 질의 중 정답 조문이 지정된 92개를 평가했다. 사용자가 만든 합성 PDF 40개의 **벤치마크 조항 텍스트**와 계약서 전체 조항을 사용했으며 PDF OCR·분류기·문제 후보 탐지는 실행하지 않았다. 백엔드의 기존 `GeminiReviewer`(`gemini-3.1-flash-lite`)에 기본 검색 상위 5개 조문 원문을 전달했다. 벤치마크의 문제 유형과 코드로 후보를 구성했지만 정답 조문 ID는 모델 입력에 전달하지 않았다.

계약서 31번은 누락 항목의 문구 증거 검증에 실패해 4개 질의의 선택 결과가 없다. 유효 응답 88개에서 검색 1위의 잠정 정답 일치는 28개, 상위 5개 포함은 40개였다. Gemini가 선택한 인용 ID 중 잠정 정답 조문이 하나라도 있는 질의는 **39/88**이었다. 그중 **11개**는 검색 1위가 정답이 아니었지만 상위 5개에서 정답을 골랐다. 반면 21개는 인용을 보류했고, 28개는 인용했지만 잠정 정답 조문과 일치하지 않았다. 총 81개 인용 중 잠정 정답 조문과 일치한 것은 49개였다. 여러 조문을 인용할 수 있어 39/88은 단일 조문 선택 정확도가 아니다.

백엔드의 추가 출처·적용일 검증까지 통과한 질의는 **13/88**이고, 그중 잠정 정답과 일치한 것은 **7개**다. 전체 81개 인용 중 64개는 기록된 시행·스냅샷 날짜가 계약 체결일 2026-02-20보다 늦어 제외된다. 현재 corpus에 과거 법령 버전이 없는 점이 이 병목에 영향을 준다. 이 검증을 통과했다는 사실도 조문이 설명을 의미상 뒷받침한다는 보장은 아니다. 따라서 상위 5개 안의 정답을 LLM이 자주 골랐다는 결과를 실제 서비스의 법적 판단 정확도로 해석하면 안 된다.

Gemini가 `LEGAL_RISK`처럼 누락 판단이 아닌 항목에도 누락 항목 전용 문서 증거 필드를 채워 응답 전체가 거부되는 문제를 확인했다. 백엔드는 해당 항목에서 사용하지 않는 필드를 폐기하도록 수정했고, 누락 항목의 문서 인용 검증은 그대로 유지했다. 백엔드 관련 테스트 13개가 통과했다.

## 테스트 입력 날짜 변경 재평가

원본 계약 체결일 `2026-02-20`은 그대로 두고, **Gemini 평가 입력에만** `2026-11-13`을 적용해 다시 실행했다. 후보 조문의 최신 기록 날짜는 `2026-10-08`이다. 검색 결과와 후보 순위도 바꾸지 않았다. 두 실행에서 모두 유효한 86개 질의로 비교하면 다음과 같다.

| 입력 날짜 | 잠정 정답 조문 인용 | 출처·적용일 검증 통과 | 검증 통과와 잠정 정답 일치 |
| --- | ---: | ---: | ---: |
| 원본 2026-02-20 | 38/86 | 12/86 | 6/86 |
| 테스트 전용 2026-11-13 | 38/86 | **65/86** | **38/86** |

테스트 날짜 실행의 검색 1위 잠정 정답 일치는 27/86, 상위 5개 포함은 39/86이었다. Gemini는 38개에서 잠정 정답 조문을 인용했지만, **27개에서는 인용한 조문이 잠정 정답과 일치하지 않았다**. 21개는 인용을 보류했다. 계약서 31번과 37번은 누락 항목 문서 증거 검증에 실패해 6개 질의가 선택 평가에서 제외됐다. 날짜 변경은 프롬프트 입력과 적용일 검증을 함께 바꾸므로, 인용 선택 결과의 차이를 날짜만의 인과 효과로 해석하지 않는다. 실제 2026-02-20 계약에 이 테스트 날짜를 적용해 판단할 수 없다.

재실행: `CheckIt_BE` 루트에서 `PYTHONPATH=. .venv/bin/python ../CheckIt_Data/test/rag/comparisons/top5_rerank_20261113/evaluate_selection.py --effective-date 2026-11-13`. 결과는 `outputs/rag/benchmark40_selection_effective_20261113.jsonl`에 별도로 기록한다.

## 후보 풀에서 5위 승격 시험

전체 후보 풀에서 기존 상위 5개 밖의 조문을 BGE Reranker로 채점하고, 가장 높은 후보의 raw logit이 현재 5위보다 충분히 높을 때만 5위를 교체했다. 1~4위는 고정했다. 계약 조항 개발셋 50개에서 점수 차이 `2.0`을 선택한 뒤 40개 계약서 벤치마크 92개에 그대로 적용했다. 이 점수는 정확도 확률이 아니다.

| 자료 | 기본 Hit@1 | 시험 Hit@1 | 기본 Hit@5 | 시험 Hit@5 | 5위 교체 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 계약 조항 개발셋 50개 | 31/50 | 31/50 | 42/50 | **43/50** | 19개 |
| 계약서 벤치마크 92개 | 30/92 | 30/92 | 43/92 | **43/92** | 41개 |

벤치마크의 41개 교체에서 잠정 정답을 새로 넣거나 기존 정답을 밀어낸 사례는 없었다. 후보 풀의 정답 포함은 70/92였지만, 이 점수 규칙이 그중 빠진 정답을 상위 5개로 옮기지 못했다. 질의당 검색·전체 후보 재정렬 시간은 평균 약 1.25초였다. 따라서 기본 검색에 적용하지 않는다. [재현 스크립트](trial_pool_promotion.py)와 로컬 결과 `outputs/rag/pool_promotion_dev50_20261113.json`, `pool_promotion_benchmark40_20261113.json`에 입력·인덱스 SHA-256, 모델 revision, 질의별 결과를 보존했다.

원자료는 `outputs/rag/benchmark40_baseline_20261113_*`, `benchmark40_top5_rerank_20261113_*`, `top5_rerank_contract50_20261113_*`, `benchmark40_selection_20261113.jsonl`, `benchmark40_selection_effective_20261113.jsonl`에 있다. [집계와 입력 해시](summary.json), [선택 평가 스크립트](evaluate_selection.py)를 함께 보존했다. 벤치마크는 합성 자료이며 정답은 `PROVISIONAL_UNREVIEWED`이다. 최종 Test split은 순위 규칙이나 프롬프트 튜닝에 사용하지 않았다.
