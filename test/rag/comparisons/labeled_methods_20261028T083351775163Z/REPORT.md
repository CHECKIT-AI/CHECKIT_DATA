# 라벨+원문: 검색 방식 공통 보정 비교

2026-10-28. 503청크, 동일 합성 조항 30개와 수동 라벨. 서비스 기본 설정과 운영 라벨 정책은 변경하지 않았다.

## 공통 실험 정책

- 데이터: retrieval_labeled_clauses_v001.jsonl. 실제 계약서 원본이나 실제 분류 모델 예측이 아닌 합성 DRAFT + 수동 주제 라벨이다.
- 원문으로 각 방식의 상위 20개 후보를 검색한다. 하이브리드는 각 검색기 20개 후보를 동일 가중치 RRF(rrf_k=60)로 결합한 상위 20개다.
- 기존 matched_labels 규칙은 공유한다. 각 방식의 원래 순위에 대해 score=-rank+(라벨 일치 시 1.5)를 적용한다. 라벨 일치 후보가 바로 앞 비일치 후보만 추월할 수 있고 순위 이동은 최대 한 칸이다. 그 외는 보정하지 않으며 여러 라벨 일치도 가산점을 누적하지 않는다.
- 원점수의 단위가 달라 cosine/BM25/RRF 점수에 같은 수치 가산점을 주지 않는다. 실험 규칙은 실행 전에 고정했으며 이 개발셋 점수로 최적화하지 않았다.
- baseline과 보정은 질의별 동일 검색 결과에 적용했다. 지연시간 비교는 하지 않았다.
- 현재 서비스의 dense 점수 +0.015 정책은 별도 참고 행이다. 공통 실험 정책과 다른 정책이므로 검색기만 바꾼 비교로 혼동하지 않는다.

## 현재 서비스 정책 참고

현재 dense + cosine 점수 보정(+0.015): Hit@1 70.0%(21/30), Hit@5 93.3%(28/30), MRR@10 0.7828. 기존 결과를 재현했다. 공통 순위 보정에서는 dense Hit@1이 63.3%로 낮아져 라벨 사용이 항상 이득은 아니었다.

기존 prioritize를 BM25에 그대로 사용하면 가산점이 0이며, 하이브리드에서는 cosine_distance가 있는 후보에 벡터 점수를 사용하므로 RRF 순위가 보존되지 않을 수 있다. 따라서 기존 함수를 세 검색기 공통 정책이라고 사용하지 않았다. 이번 작업에서는 해당 운영 코드를 변경하지 않았다.

## 해석 및 재현

- 공통 정책의 Hit@5는 모두 28/30으로 동일하다. BM25의 Hit@1 25/30이 이 작은 표본에서 가장 높지만, 현재 dense 정책과 비교한 차이는 4개 질의이며 실제 모델 라벨 기반 종단간 우월성을 입증하지 않는다.
- 하이브리드는 보정으로 Hit@5 26/30 → 28/30이지만 다른 방식보다 더 높은 Hit@5를 보이지 않았다.
- 전체 90개 비교와 달리 이번 비교는 서비스 입력에 가까운 조항 30개에 한정한다. 새로운 독립 평가셋이 아니라 기존 개발셋 재사용이다.
- 실제 모델이 예측한 라벨, 독립 조항, 전문가 검수 정답으로 검증하기 전에는 운영 기본값을 변경하지 않는다.
- 후보 보존·그 외 무보정·최대 한 순위 이동의 기본 검증과 인덱스 해시/ID/개수·정답 조문 존재 검증을 통과했다.
