# 현재 503청크 인덱스의 순위 개선 실험 (2026-11-12)

`employment_basic_v004`에서 기존 BGE-M3 dense 상위 5개에 BM25 순위에 따른 보너스 `5 / BM25 순위`를 적용해 재정렬했다. BM25 상위 10개에 없는 조문은 보너스가 없다. BM25 1위 조문이 상위 5개에 없으면 5위에 넣는다. 동일 조문은 중복 반환하지 않는다. 검색기 점수는 정확도 확률이 아니다.

| 개발 평가셋 | 질의 | dense Hit@1 | 새 방식 Hit@1 | dense Hit@5 | 새 방식 Hit@5 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 기존 질의 | 90 | 72.2% | **78.9%** | 95.6% | **97.8%** |
| 현재 파일의 계약 조항 | 50 | 56.0% | **62.0%** | 80.0% | **84.0%** |
| 추가 법령 질의 | 42 | 78.6% | **83.3%** | 100.0% | 100.0% |
| 추가 표현 | 14 | 42.9% | **64.3%** | 64.3% | **78.6%** |

같은 데이터 파일·인덱스 해시끼리 조항 원문 검색만 비교했으며 분류 라벨 보너스는 적용하지 않았다. 50개 자료는 이전 실행 뒤 파일 SHA-256이 달라졌으므로 2026-11-10에 저장된 68%/94% 결과를 기준선으로 사용하지 않고 현재 파일로 dense를 재실행했다. 정확한 해시와 비반올림 수치는 [comparison.json](comparison.json)에 있다. 모두 합성·미검수 개발 자료이며, 90개와 추가 표현 자료는 이전 검색 보완에도 사용됐다. 따라서 독립적인 최종 성능 수치가 아니다.

BM25 1위가 dense 상위 5개 밖에 있을 때만 후보를 넣어 기존 90개에서 놓친 조항 2개, 계약 조항 50개에서 2개, 추가 표현 14개에서 2개를 새로 찾았다. 이 개발 자료에서는 새로 놓친 정답이 없었으나, 다른 질의에서 같은 결과를 보장하지 않는다. 기존 90개 중 여전히 2개를 놓친다.

같은 90개에서 `hybrid_rerank`는 Hit@1 71.1%, Hit@5 91.1%, 평균 2.2초(이 실행의 MPS)였고, 80:20 `weighted_rrf`는 75.6%/94.4%였다. 두 방식은 dense의 두 지표를 동시에 넘지 못했다. 새 방식을 `dense_bm25_top5`라는 **명시적 실험 옵션**으로만 추가했고 서비스 기본 `dense` 및 백엔드 기본값은 변경하지 않았다. 이 실험 방식은 BM25에서 가져온 후보와 dense 후보의 점수 단위가 달라 조항 서비스에서도 라벨 가산점을 적용하지 않는다. 실제 모델 예측 라벨을 포함한 종단간 평가와 독립 검수 정답이 필요하다.

재현: 저장소 루트에서 `.venv/bin/python -m RAG.pipelines.evaluate --corpus employment_basic_v004 --method dense_bm25_top5 --dataset test/rag/datasets/retrieval_dev_v002.jsonl --device cpu`. 다른 평가셋은 `retrieval_contract_2026_dev_v001.jsonl`, `retrieval_supplements_v001.jsonl`, `retrieval_paraphrases_v001.jsonl`로 바꾼다. 실행 결과는 `outputs/rag/`에 저장한다.
