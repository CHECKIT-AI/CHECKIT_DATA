# 기본 근로조건 통합 인덱스 검증·검색 평가

평가일: 2026-10-28. 대상: `employment_basic_v002`, 498청크. 기본 서비스와 같은 **BGE-M3 dense 검색**을 평가했다. 모델·청킹·가중치·검색 설정은 평가 결과에 맞춰 변경하지 않았다.

## 결론

- 저장·버전·출처·벡터 무결성 **17/17개 검사 통과**. 저장 무결성 통과는 법률 해석의 정확성이나 자료 완전성을 뜻하지 않는다.
- 기존 90개 개발 질의에서 Hit@5 **85.6%(77/90)**. 이전 444청크와 같고, 근로기준법 단독 131청크의 91.1%보다 낮다.
- 추가 범위 42개 개발 질의에서 Hit@5 **97.6%(41/42)**, Hit@1 **76.2%(32/42)**. 실제 계약서·전문가 검수 평가의 정확도가 아니다.
- 원문 이미지 태그 2개, 날짜 자동 필터 미구현, 참조 별표 일부 미수집 등의 한계가 있다.

## 1. 데이터와 인덱스 검증

`integrity_audit.json` 및 `../../audit_employment_basic_v002.py`에 검사 결과와 재실행 코드를 보존했다.

- 12개 법령 본칙 507개 중 삭제 13개 제외 → 494개. 선택 별표 3개와 고시 1개를 합쳐 498개.
- 12개 API 본문의 SHA-256·법령 ID·법령명·시행일·기준일 확인 및 원본 재정규화 결과 일치.
- 가공·인덱스 입력 해시와 레코드 고유 ID 일치. 기존 444개 청크와 기존 두 인덱스의 입력 보존 확인.
- Chroma의 498개 문서 본문·메타데이터·ID와 입력 레코드 일치. 고시의 적용 기간 메타데이터도 일치.
- 모든 벡터가 유한한 1,024차원 정규화 벡터. BM25 498개 및 입력 해시 일치.
- 공식 PDF 4개(고시 1개·별표 3개)의 파일 형식·기록 해시 확인. 고시 추출 텍스트·적용 기간 확인.

감사 명령:

```bash
python3 test/rag/audit_employment_basic_v002.py
```

이 검사는 로컬 원본과 수집 당시 manifest의 일치 여부를 확인한다. 공식 사이트에 더 최신 개정이 있는지 재조회한 결과가 아니며, 모든 법령·별표에 대한 전문가 검수를 대체하지 않는다.

## 2. 동일 90개 질의의 인덱스 비교

기존 `retrieval_dev_v002.jsonl`의 동일한 문장·정답을 세 인덱스에 적용했다. 세 실행의 데이터셋 해시는 같으며 CPU, dense, 최종 10개 조건으로 순차 실행했다. 질의 임베딩 모델은 각 인덱스 manifest의 동일 BGE-M3 커밋을 사용했다.

| 인덱스 | 청크 | Hit@1 | Hit@5 | Hit@10 | MRR@10 | 평균 검색 시간 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 근로기준법 단독 | 131 | 73.3% | 91.1% | 92.2% | 0.8142 | 55.41ms |
| 기존 8개 법령 | 444 | 65.6% | 85.6% | 91.1% | 0.7509 | 55.15ms |
| 현재 12개 법령·선택 별표·고시 | 498 | 63.3% | 85.6% | 90.0% | 0.7378 | 57.16ms |

시간은 모델 로딩·워밍업·평가용 DB 복사를 제외한 질의 준비·검색의 단일 실행 평균이다. 서비스 전체 응답시간이나 통계적인 우열을 뜻하지 않는다.

### 현재 인덱스의 질의 유형별 결과

| 유형 | 수 | Hit@1 | Hit@5 | Hit@10 |
| --- | ---: | ---: | ---: | ---: |
| 키워드 | 30 | 70.0% | 90.0% | 96.7% |
| 사용자 질문 | 30 | 60.0% | 90.0% | 93.3% |
| 계약서 문장 | 30 | 60.0% | 76.7% | 80.0% |

기존 444개 대비 Hit@5에서 새로 맞힌 질의와 놓친 질의는 모두 0개다. Hit@1은 대표 정답을 1위에서 놓친 질의가 2개이고, 새로 1위가 된 질의는 없다. 다만 다음 2개는 기존 정답의 상위·하위 규정이 경쟁한 것으로, 무조건 잘못된 검색으로 해석하면 안 된다.

- “예고 없는 해고 예고수당 예외”: 새 1위는 근로기준법 시행규칙 제4조.
- “근로시간 연장 한도 특별연장근로 인가”: 새 1위는 근로기준법 시행규칙 제9조.

“임금과 소정근로시간 등은 구두로 설명하며 별도 서면을 제공하지 않는다.”는 대표 정답 제17조가 기존 444개 인덱스의 9위에서 새 인덱스의 10위 밖으로 밀렸다. 검색 범위를 늘려도 대표 정답 순위가 자동 개선되지는 않는다.

90개는 근로기준법 중심의 기존 DRAFT 개발셋이며 질의별 대표 정답 1개만 있다. 이미 이전 개선에 사용한 자료이고, 통합 인덱스의 다른 관련 조문은 정답에 포함되지 않을 수 있다. 이 수치로 모든 관련 법령 검색의 정확도를 단정할 수 없다.

## 3. 추가 범위 42개 개발 질의

데이터셋: `../../datasets/retrieval_supplements_v001.jsonl`. 신규 원문을 읽고 해당 검색 실행 전에 고정한 **14개 주제 × 키워드·사용자 질문·상황 설명 각 1개**다. 대표 목표 레코드 14개는 모두 기존 444개 인덱스에는 없었다. 54개 추가 청크 중 14개 목표를 표본 평가했으며, 전수 내용 검증이 아니다.

유일한 Hit@5 실패는 “어린이날이 일요일과 겹치면 대체로 쉬는 날을 어떻게 정하나요?”다. 목표인 공휴일 규정 제3조는 **6위**, 1위는 근로기준법 제55조였다. 부모 규정과 구체 규정의 우선순위 조정이 필요한 사례다. 소규모 사업장 기간제법 적용표는 3개 질문 모두 상위 5개에는 있지만 1위인 경우가 없었다.

**해석 제한:** 질문은 실제 사용자·계약서 수집본이 아니라 수집 원문을 바탕으로 작성한 합성 DRAFT다. 조문 표현과 겹치는 단어가 있고, 이전 API 동작 확인에서도 같은 주제 일부를 사용했다. 주제당 3문장은 서로 독립인 표본이 아니며, 정답도 작성자가 원문에 근거해 지정했다. 전문가·독립 검수와 미사용 실제 입력 평가가 필요하다. 97.6%를 실제 계약서 분석 정확도나 최종 성능으로 발표해서는 안 된다.

단순 이항 표본으로 계산한 Hit@5 Wilson 95% 구간은 기존 90개에서 약 76.8~91.4%, 추가 42개에서 약 87.7~99.6%다. 주제 내 상관관계·정답 오류·실제 환경 차이를 반영하지 않으므로 실제 일반화 성능의 보장 구간이 아니다.

## 4. 발견된 품질 한계

1. **이미지 태그 잔존 2개:** 근로자퇴직급여 보장법 시행령 제8조(기존)와 최저임금법 시행규칙 제2조(신규)에 `<img>` 또는 이미지 대체 문자 등이 남아 있다. 저장 오류가 아니라 공식 API 응답의 표현을 그대로 보존한 결과다. 원문은 유지하되 별도 검색용 텍스트에서 정리하고 재평가할 필요가 있다.
2. **참조 자료 미완성:** 근로기준법 시행규칙 제4조가 참조하는 별표 1, 제11조의2·제12조의3의 별표, 최저임금법 시행규칙 제3조의 별표 3 등은 현재 498개 청크에 포함되지 않는다. 본문 검색 성공이 참조 기준 전체 확보를 뜻하지 않는다.
3. **시행일 자동 필터 없음:** 2026년 고시를 다른 연도 질문에도 반환할 수 있다. 현재 고시의 기간 메타데이터 보존은 확인했지만 기간별 검색·판정 기능은 검증 대상 기능 자체가 아직 없다.
4. **답변·법률 판정은 평가하지 않음:** 이번 지표는 지정한 근거가 검색되는지에 대한 것이다. 금액 계산·사업장 규모·근로시간 등 적용 조건 판단과 위법·누락·사기 탐지 정확도가 아니다.

평가 중 원문·청크·모델·실행 중 서비스 인덱스를 바꾸지 않았다. 위 한계에 대한 개선은 별도 버전에서 수행하고 같은 개발셋 및 독립 평가셋으로 비교해야 한다.

## 5. 재현과 결과 파일

```bash
python3 -m RAG.pipelines.evaluate --corpus employment_basic_v002 \
  --method dense --dataset test/rag/datasets/retrieval_dev_v002.jsonl \
  --run-name employment_basic_v002_legacy90 --device cpu
python3 -m RAG.pipelines.evaluate --corpus employment_basic_v002 \
  --method dense --dataset test/rag/datasets/retrieval_supplements_v001.jsonl \
  --run-name employment_basic_v002_supplements42 --device cpu
```

기존 인덱스 비교는 첫 명령의 corpus만 `employment_laws_v001`, `labor_standards_v001`로 바꿔 순차 실행한다. 현재 PC의 원본·모델 캐시·인덱스가 필요하며, 기존 인덱스는 덮어쓰지 않는다.

- `integrity_audit.json`: 17개 검사 결과·출처별 결과·품질 경고.
- `comparison.json`: 집계 지표·주제별 결과·기존 인덱스 대비 개선/후퇴 질의.
- 각 실행 폴더의 `summary.json`, `results.csv`, `results.jsonl`, `run_metadata.json`: 질의별 순위, 상위 결과, 데이터·코드 해시, 모델 커밋, 환경.

질의당 정답 1개여서 이번 Hit와 Recall 값은 같다. 최종 깊이는 10개이며, 출력된 순위가 없으면 10위 밖이라는 뜻이다.
