# 503청크 검색 방식 재평가

2026-10-28. 현재 `employment_basic_v004` 인덱스로 세 검색 방식을 실제 재실행했다. 서비스의 기본 검색 설정 및 인덱스는 변경하지 않았다.

## 평가 조건

- corpus: 근로관계 12개 법령 본칙 494청크 + 선택 별표 8개 + 2026년 최저임금 고시 1개 = 503청크.
- 질의: 기존 `test/rag/datasets/retrieval_dev_v002.jsonl` 90개(키워드 30, 사용자 질문 30, 계약서 조항 30). 새로 추가된 법령 영역을 전부 평가하는 데이터셋은 아니다.
- 세 실행의 평가 파일 SHA-256 동일: `0e0130fd892bc43d4eef282dd333b8cd689acf4c5ba1b19259c13a456dba79fd`.
- 하이브리드: 각 검색기 후보 20개, 동일 가중치 RRF, rrf_k=60. 추가 reranker 및 라벨 가산점 없음.
- BGE-M3 및 BM25도 라벨 가산점 없이 입력 텍스트만 사용. 따라서 현재 서비스의 라벨+원문 정책 전체 성능을 측정한 것은 아니다.
- CPU, 질의 임베딩/모델은 인덱스 manifest 설정 준수. 기존 CLI의 청크 해시·인덱스 ID/개수·정답 조문 존재 여부 검사를 통과했다.
- Hit@5: 대표 정답 조문이 상위 5개 결과에 포함된 질의 비율.

## 전체 90개: 이전 기준선과 비교

| 방식 | 이전 131청크 Hit@5 | 현재 503청크 Hit@5 | 현재 적중 수 | 변화 |
|---|---:|---:|---:|---:|
| BGE-M3 벡터 검색 | 91.1% | 95.6% | 86/90 | +4.4%p |
| BM25 키워드 검색 | 81.1% | 86.7% | 78/90 | +5.6%p |
| 하이브리드 (동일 가중치 RRF) | 87.8% | 93.3% | 84/90 | +5.6%p |

이전 수치는 README의 131청크 기준선이다. 현재 수치는 청크 확대뿐 아니라 검색용 표현 보완 등 현재 버전의 변경을 함께 포함하므로 청크 수 증가만의 인과 효과로 해석하지 않는다.

|---|---:|---:|---:|---:|
| 키워드 | 30 | 96.7% (29/30) | 100.0% (30/30) | 100.0% (30/30) |

| 계약서 조항 | 30 | 93.3% (28/30) | 93.3% (28/30) | 86.7% (26/30) |

## 해석과 한계

- 전체 Hit@5는 BGE-M3가 가장 높다. 계약서 조항 30개에서는 BGE-M3와 BM25가 동일하고, 해당 하위집합 Hit@1은 각각 66.7%, 80.0%이다. BM25가 조항 입력에 항상 불리하다고 일반화할 수 없다.
- 전체 하이브리드 Hit@1은 78.9%로 BGE-M3 72.2%보다 높지만 Hit@5는 낮다. 이 결과만으로 모든 지표에서 한 방식이 우월하다고 결론 내리지 않는다.
- 질의는 합성 DRAFT 개발셋이며 결과를 보며 보완한 이력이 있다. 실제 계약서·실제 분류 모델 출력·전문가 검수 정답을 이용한 독립 최종 평가가 아니다.
- 하이브리드는 이번 동일 가중치 설정만 평가했다. 가중치 최적화 또는 reranker 추가 효과는 이번 결과에 포함되지 않는다.
- 과거와 같은 90개 개발 질의를 사용해 새 인덱스에서 재평가했다. 추가 법령 전체의 커버리지/정확도를 보장하지 않는다.

## 산출물 및 재현

각 방식의 summary.json, run_metadata.json, results.csv를 하위 폴더에 보존했다. 전체 검색 원문 결과는 comparison.json에 기록된 로컬 outputs/rag 실행 폴더의 results.jsonl에 있다.

```bash
.venv/bin/python -m RAG.pipelines.evaluate --corpus employment_basic_v004 \
  --dataset test/rag/datasets/retrieval_dev_v002.jsonl --method dense --device cpu
# --method bm25 및 --method hybrid로 각각 실행
```
