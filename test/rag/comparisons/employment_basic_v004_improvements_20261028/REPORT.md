# RAG 실패 사례 보완 및 전후 평가

2026-10-28. 적용 버전: **employment_basic_v004**, 503개 청크, **BGE-M3 dense**. 기존 원문·인덱스와 평가셋을 보존했다.

## 변경 내용

1. **법률 용어와 일상 표현 연결:** 근로조건 명시·위약 예정·전차금 상계·금품 청산·휴게·휴일·대체공휴일 7개 조문에 검색용 보충어를 추가했다. 용어는 공식 원문과 분리해 `search_hints` 및 `embedding_text`에만 기록한다. 응답의 `content`는 공식 원문 그대로다. `RAG/config/search_concepts.json`에 원문 근거 발췌·버전을 기록했다. 이 주석은 평가 오류 분석 후 작성했으며 전문가 검수 상태는 PENDING이다.
2. **검색용 본문 정리:** 이미지 HTML 태그, 표 테두리·과도한 패딩을 검색용 표현에서 정리했다. 숫자·부정어·표 셀 구분을 유지한다. 원문 이미지의 누락 글자를 복원한 것은 아니며 원문 자체를 덮어쓰지 않는다.
3. **빠진 참조 별표 5개 보완:** 근로기준법 시행규칙 별표 1·2·3, 최저임금법 시행규칙 별표 3, 퇴직급여법 시행규칙 별표를 공식 API 원본에서 추출했다. 삭제된 최저임금 시행규칙 별표 1·2는 제외했다. 기존 별표 3개와 합쳐 총 8개 별표다. 별도 PDF 5개를 새로 내려받은 것은 아니며 원본 JSON과 PDF 출처 링크를 보존한다.
4. **고시 연도 혼입 방지:** 질문에 명시된 연도와 연간 고시의 기간을 대조한 뒤 최종 개수로 자른다. 수집하지 않은 연도는 API `warnings`로 알린다. 일반 법령의 과거 버전 복원·모든 적용 조건 판정·연도 없는 질문의 기간 추정은 지원하지 않는다.

## 고정 개발셋 전후 결과

| 평가셋 | 보완 전 Hit@1 | 보완 후 Hit@1 | 보완 전 Hit@5 | 보완 후 Hit@5 |
| --- | ---: | ---: | ---: | ---: |
| 기존 근로기준법 중심 90개 | 63.3% | 72.2% | 85.6% | 95.6% |
| 추가 자료 합성 42개 | 76.2% | 78.6% | 97.6% | 100.0% |
| 추가 표현 합성 14개 | 28.6% | 42.9% | 42.9% | 64.3% |

기존 90개에서는 상위 5개 정답이 77→86개로 늘었다. 새로 맞힌 질의 9개, 기존 정답을 놓치게 된 질의 0개다. 추가 42개는 41→42개로 늘었고 기존 정답 누락은 없다. 추가 표현 14개는 6→9개로 늘었다. 서로 다른 평가셋 점수를 합쳐 서비스 정확도로 제시하지 않는다.

청소·별표 보완만 적용한 중간 버전 v003은 기존 90개 Hit@5 85.6%, 추가 42개 97.6%로 보완 전과 같았다. 최종 보충어 적용 뒤 점수가 개선됐다. 중간 재정렬 실험에서도 위약금 일부가 10위 밖에 남아 해당 실험을 중단했다. 재정렬의 전체 132개 점수는 산출하지 않았고 최종 서비스는 재정렬을 사용하지 않는다.

기존 90개 기준 MRR@10은 0.7378→0.8178, 평균 검색 시간은 57.16→55.07ms였다. 모델 로딩·워밍업·DB 복사를 제외한 단일 CPU 실행 수치이며 API 전체 지연이나 통계적 우열을 보장하지 않는다.

원인별로 보면, 짧은 공식 문구와 일상어의 차이를 보충어로 연결했고, 일반 휴일 규정 대신 대체공휴일의 구체 규정을 찾도록 표현을 보완했다. 이는 검색 근거 순위의 변화이며 각 문장의 적법·위법 판정 결과가 아니다.

## 남은 실패를 포함한 한계

기존 90개에서 아직 상위 5개 밖인 질의는 다음 4개다.

| 질문 | 목표 | 현재 순위 |
| --- | --- | ---: |
| 임금 구성항목 계산방법 지급방법 서면 교부 | 제17조 | 6 |
| 그만두면 무조건 백만 원을 내라는데 어떤 규정을 찾아봐야 하나요? | 제20조 | 10위 밖 |
| 약속한 기간을 채우지 않고 일을 그만두는 경우 실제 손해와 무관하게 100만 원을 납부한다. | 제20조 | 10위 밖 |
| 회사가 계속 근무하는 조건으로 대여한 금액은 근로자의 월급에서 매달 차감하여 정산한다. | 제21조 | 10위 밖 |

특히 금액만 언급한 모호한 퇴사 조건이나 대여금·임금 공제가 섞인 복합 문장은 개선되지 않았다. 이를 해결하려면 근로관계·계약기간·손해배상 약정·전대채권 조건을 보존하는 질의 표현 개선과 독립 검수가 필요하다. 숫자가 있다고 위약금으로 단정하는 규칙은 추가하지 않았다.

**추가 표현 14개에서도 5개를 놓쳤다.** 따라서 기존 90개에서 95.6%가 됐다고 실제 계약서 일반화 문제가 해결된 것은 아니다. 이 14개 역시 실패 유형을 바탕으로 같은 작성자가 새 버전 검색 전에 만든 합성 DRAFT이며, 독립 최종 평가가 아니다.

기존 90개와 42개는 오류 분석에 직접 사용했고, 그 결과로 검색 주석을 작성했다. 개선 수치는 개발셋에 대한 결과다. 사용자 문서 수집·전문가 검수·여러 관련 조문의 정답 지정·미사용 평가가 필요하다. 라벨 분류·금액 계산·위법/누락/사기 탐지·LLM 설명 정확도는 이번 실험의 평가 대상이 아니다.

## 실행·출처 기록

- `comparison.json`: 각 실행 지표, 전체 질의의 전후 순위, 개선/후퇴 건수.
- 실행별 폴더: `results.jsonl/csv`, `summary.json`, `run_metadata.json`(데이터·코드 해시·모델 커밋·설정).
- `integrity_audit.json`: 최종 데이터·공식 원문·검색 주석·벡터 검사.
- `api_smoke.json`: 실제 인증·CSRF를 포함한 API 8건. 개선 사례와 신규 별표, 2025년 고시 제외·경고를 확인했다. 기존 production HTTPS 설정은 유지하고 루프백 요청에서 쿠키 전달을 명시했다.

```bash
python3 -m RAG.pipelines.prepare_search_improvements
python3 -m RAG.pipelines.prepare_search_concepts
```

위 준비 명령은 각각 v003·v004 산출물이 없는 환경에서만 실행한다. 공식 원본과 v002 가공 데이터가 먼저 있어야 한다. 인덱스는 `build_index --corpus employment_basic_v004`와 `build_bm25 --corpus employment_basic_v004`로 별도 생성한다. 현재 PC에는 모두 구축돼 있어 재실행할 필요가 없다.

```bash
python3 test/rag/audit_search_improvements.py
python3 -m RAG.pipelines.evaluate --corpus employment_basic_v004 --method dense \
  --dataset test/rag/datasets/retrieval_dev_v002.jsonl --run-name v004_dense_legacy90 --device cpu
```

추가 평가셋은 `retrieval_supplements_v001.jsonl`, `retrieval_paraphrases_v001.jsonl`로 바꿔 실행한다. 모든 평가셋의 질의당 대표 정답은 1개이므로 Hit와 Recall 값은 같다.
